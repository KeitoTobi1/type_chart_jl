# TypeChart.jl: ポケモンタイプ相性のゲーム理論・ナッシュ均衡分析

ポケモンのタイプ相性表に基づき、ゲーム理論における**ナッシュ均衡（Nash Equilibrium）**混合戦略確率を計算・分析するJuliaパッケージです。

本プロジェクトは、Vlad Firoiu 氏による Python 実装 [**vladfi1/pokemon-nash**](https://github.com/vladfi1/pokemon-nash/) をベースに着想を得て、Julia言語へ完全移植し、大幅な機能拡張・多世代対応を行ったものです。

対応している相性環境：
1. **フェアリータイプ登場後（第6世代〜現代: Gen 6+）**
   - 18タイプ（フェアリータイプ追加）
   - はがねタイプの耐性変更（ゴースト技・あく技が等倍化）
2. **中世代（第3〜5世代: Gen 3〜5 / vladfi1氏の元実装の仕様）**
   - 17タイプ（あく・はがね追加、フェアリー未登場）
   - はがねタイプの超耐性（ゴースト技・あく技も半減）
   - あく/ゴースト複合の「弱点なし」環境
3. **初代（赤・緑・青・ピカチュウ: Gen 1）**
   - 15タイプ（あく・はがね・フェアリーなし）
   - **初代ゴーストタイプの設計ミス反映**: ゴースト技 → エスパータイプが無効（0.0倍）
   - 初代固有相性: むし技 ↔ どく技が互いに抜群（2.0倍）、こおり技 → ほのおタイプが等倍（1.0倍）

## 主な機能と数理モデル

1. **単タイプ同士の対称ナッシュ均衡 (`symmetric_matchup_matrix`)**
   - 攻撃側と防御側が互いに最善の技を使ったときの倍率を比較し、勝敗を判定（+1, -1, 0）。
   - 反対称行列（$A = -A^T$）に対するゼロサムゲームのナッシュ均衡混合戦略を線形計画法（LP）で算出。
2. **複合タイプ同士の対称ナッシュ均衡**
   - 単タイプ＋2タイプ複合（全ペア）の対称マッチアップゲームにおけるナッシュ均衡。
3. **単タイプ攻撃 vs 複合タイプ防御の非対称ゼロサムゲーム (`asymmetric_matchup_matrix`)**
   - 利得行列は「攻撃側が与える最善ダメージ倍率」。
   - 行プレイヤー（攻撃側）は最小ダメージを最大化（Maximin）、列プレイヤー（防御側）は最大被ダメージを最小化（Minimax）する最適戦略およびゲーム価値を、JuMP + HiGHS による線形計画問題として求解（pygambit等への外部依存なし）。

## 使い方

### 1. 実行方法

すべての世代（現代相性と初代相性の両方）を実行して結果を出力します：

```bash
julia --project=. run.jl
```

特定の世代のみ実行する場合：

```bash
# フェアリー登場後（Gen 6+）のみ
julia --project=. run.jl gen6

# 初代（Gen 1: ゴースト設計ミスあり）のみ
julia --project=. run.jl gen1

# 第3世代（Gen 3: 旧仕様）のみ
julia --project=. run.jl gen3
```

### 2. テストの実行

```bash
julia --project=. test/runtests.jl
```

## 計算結果の比較（抜粋）

### 単タイプ Nash 均衡確率
- **現代 (Gen 6+)**:
  - `steel` (15.8%), `water` (15.8%), `dragon` (15.8%), `ground` (10.5%), `ghost` (10.5%), `fairy` (10.5%), `electric` (10.5%)
  - 耐性の多いはがね・みず、攻守ともに強力なドラゴン・フェアリー等にバランスよく確率が分散。
- **中世代 (Gen 3〜5)**:
  - `dragon` (21.4%), `steel` (14.3%), `fighting` (14.3%), `ghost` (10.7%), `water` (10.7%), `ground` (10.7%)
  - ドラゴンの攻撃一貫性と鋼の超耐性（霊・悪半減）が極めて強力。エスパーは過剰弱体化により 0.0% に完全転落。
- **初代 (Gen 1)**:
  - `dragon` (26.7%), `psychic` (20.0%), `rock` (20.0%), `fighting` (10.0%), `bug` (10.0%)
  - ゴーストの無効化バグとあく・はがね不在により、**エスパーとドラゴンが圧倒的な支配力**を発揮。

### 攻撃 vs 防御 非対称ゲーム (防御側複合タイプ)
- **現代 (Gen 6+)**:
  - `flying/steel` (エアームド/アーマーガア等: 19.9%), `dragon/water` (キングドラ等: 14.7%), `grass/water` (ルンパッパ等: 14.1%), `dragon/steel` (ディアルガ等: 12.8%)
- **中世代 (Gen 3〜5)**:
  - `dragon/steel` (ディアルガ等: 19.9%), `grass/water` (ルンパッパ等: 17.1%), `flying/steel` (エアームド等: 16.2%), **`dark/ghost` (ヤミラミ・ミカルゲ: 13.9%)**
  - フェアリー不在による**「弱点なし」という仕様の歪み**が、ヤミラミ等の高いディフェンダー確率として如実に現れています。
- **初代 (Gen 1)**:
  - `ghost/psychic` (50.0%), `ghost` (50.0%)
  - 初代のゴーストはノーマル・格闘が無効であり、さらにエスパーを複合するとゴースト技も無効化バグで効かないため、鉄壁の耐性となることが数理的にも実証されます。

より詳細なゲームバランスの粗さと是正の考察については、[`pokemon_type_balance_report.md`](report/pokemon_type_balance_report.md) をご覧ください。

### Julia版での主な拡張・発展点

1. **言語の刷新と数理モデリングの統合**:
   - Python実装における `pygambit`（C拡張・インストール難度高）や `scipy`、`pandas` の混在を解消し、Juliaの標準的数理最適化フレームワーク **[`JuMP`](https://jump.dev/) + [`HiGHS`](https://highs.dev/)** で統一。
   - 二人ゼロサムゲームのナッシュ均衡（ミニマックス解）を線形計画問題として美しく定式化し、外部Cライブラリ依存なしに爆速で求解可能に。
2. **多世代（Gen 1 / Gen 3〜5 / Gen 6+）への対応**:
   - 元リポジトリの第3世代相性固定から、初代（ゴースト設計ミスバグあり）および第6世代以降（フェアリー導入・鋼耐性変更）の相性を追加。
3. **世代間ゲームバランスの数理的分析機能**:
   - 世代ごとのナッシュ均衡確率を横断比較し、対戦環境の歴史や公式による相性調整の意図（なぜフェアリーが導入されたのか、なぜ鋼が弱体化されたのか）をデータから解明するレポート機能を追加。
